## 一、统一中间表示（`pflc/model/`）

### 1.1 `Anchor` — 条款锚点

```python
@dataclass(frozen=True)
class Anchor:
    doc_id: str        # 依据编号，如 "MOA-20-2018-ANNEX3" / "GB-T-31216-2014"
    doc_title: str     # 文件标题
    clause: str        # 条款位置，如 "第十一条" / "表1"
    excerpt: str       # 原文摘录（逐字，核对用）
    source_url: str    # 来源 URL（转载源如实标注）
    captured_at: str   # 抓取日期
    sha256: str        # 快照文件 sha256（可证性）
```

**纪律**：`excerpt` 必须**逐字**出现在入仓的原文快照里（核对判据）；锚点取自全文转载核对后的原文，**未核对不得生效**。

### 1.2 `LabelCard` — 标签档案（结构化中间表示）

```python
@dataclass
class LabelCard:
    card_id: str                          # 稳定身份键（内容 sha256 前缀），用于两轮对账
    raw_text: str                         # 原始标签全文
    product_name: Field                  # 通用名
    category: Field                       # 产品类别（犬粮/猫粮/其他）
    life_stage: Field                     # 生命阶段（幼年/成年/全阶段/…）
    guaranteed: Dict[str, Field]          # 成分分析保证值 键值对（Decimal）
    ingredients: Field                    # 原料组成
    additives: Field                      # 添加剂
    net_content: Field                    # 净含量
    producer: Field                       # 生产者名称与地址
    dates: Field                          # 生产日期/保质期
    claims: List[Field]                   # 宣称用语（"天然""无谷"…）
    unparsed: List[str]                   # 未能解析的字段名（如实记录）
```

### 1.3 `Field` — 单字段（三态载体）

```python
@dataclass
class Field:
    name: str
    value: Any | None            # None 表示未取得
    status: str                  # "provided" | "not_provided"
    reason: str | None           # not_provided 的原因码
    unit: str | None
    evidence: str | None         # 原文摘录（抽取依据）
```

**原因码枚举**（`reason`）：

| 码 | 语义 |
|---|---|
| `not_found` | 文本里确实没有该字段 |
| `mapping_uncertain` | **歧义**：同一表达可能指多个参数，**绝不猜** |
| `structure_broken` | 文本结构损坏，无法切分 |
| `out_of_range` | 抽到数值但超出合法范围（如粗蛋白 300%）→ 丢弃 |

### 1.4 `Finding` — 单条判定结论

```python
@dataclass(frozen=True)
class Finding:
    rule_id: str
    dimension: str        # "label" | "nutrition" | "claim"
    target: str           # 被判定的对象名（如 "粗蛋白" / "净含量"）
    verdict: str          # "compliant" | "noncompliant" | "not_provided" | "skipped" | "unknown"
    observed: str | None  # 观测到的值（人可读）
    expected: str | None  # 期望/限值（人可读，值来自规则包）
    anchor: Anchor | None # 条款锚点
    note: str | None      # 补充说明（如原因码）
```

### 1.5 `DimensionResult` / `CheckResult`

```python
@dataclass
class DimensionResult:
    dimension: str
    findings: List[Finding]
    excluded: bool = False          # 是否被排除出聚合
    exclude_reason: str | None = None   # 原因码（"no_effective_rules" | "standard_not_effective"）
    not_assessed: bool = False      # 零适用项 → 未评估（不输出 compliant）

@dataclass
class CheckResult:
    card_id: str
    dimensions: List[DimensionResult]
    overall: str                    # 聚合结论（见 §四.3）
    disclaimer: str                 # 强制免责声明
    pending_rules: List[str]        # 未生效规则清单（显式呈现）
```

## 二、解析层（`pflc/parse/`）

### 2.1 设计原则

- **规则优先**：正则 + 槽位 + 合法性校验；**无 LLM**；
- **确定性**：同一文本 → 同一档案（**逐字节一致**，配守门测试）；
- **解析不到 = 显式降级**：落 `not_provided` + 原因码，**绝不猜测补全**。

### 2.2 字段抽取策略

> **M2 回填**（本表是 M2 的主要依据，以下为实测后的最终口径）：四行有实质修订——
> 生命阶段（产品类型词不入表）、净含量（未知单位口径）、日期（合法性 + 丢弃口径）、
> 宣称用语（词表来源与传入方式）。逐条决策见 `plan/07` 决策记录 M2 各条。

| 字段 | 抽取方式 | 合法性校验 |
|---|---|---|
| 通用名 | 首个非空行 / "产品名称：" 后内容 | 长度 > 0（回退行须不像标签键值对） |
| 产品类别 | 关键词命中（犬/狗 → 犬粮；猫 → 猫粮） | 白名单枚举；**歧义（同时出现犬猫）→ `mapping_uncertain`** |
| 生命阶段 | 关键词命中（幼年/成犬/全阶段/…） | 白名单枚举；命中多个 → `mapping_uncertain`。**产品类型词（如"全价"）不得进别名表**——它不是生命阶段，混入会让正常标签误判歧义，进而使营养维度整维度 `not_assessed`（M2 修正） |
| 保证值 | 正则抓 `指标名 + 比较符 + 数值 + 单位` | **范围校验**：粗蛋白/粗脂肪/水分/灰分 ∈ [0,100]；超范围 → `out_of_range` 丢弃 |
| 原料组成 | "原料组成/配料" 标签后内容 | 长度 > 0 |
| 添加剂 | "添加剂" 标签后内容 | 长度 > 0 |
| 净含量 | 正则抓"关键词 + 数值"，单位按**最长优先**的已知表判定（g/kg/斤/斤…） | 单位白名单；**未知单位 → `mapping_uncertain`**（不是 `not_found`——"写了但单位不认识" ≠ "根本没写"）。最长优先是必须的：`2kg` 不得被读成 `2 g` |
| 生产者 | "生产企业/委托方/地址" 标签后内容 | 长度 > 0 |
| 生产日期/保质期 | 日期正则 + "保质期" 关键词 | **日期合法性**：`datetime.date()` 校验（月 ≤12 / 日 ≤31 / 组合真实存在）；非法 → `out_of_range` 且**丢弃该字段**（绝不"标个非法还当已提供"，否则存在性规则判 compliant = 假合规）；原文片段留 `evidence` 可核 |
| 宣称用语 | 词表命中（"天然""无谷""无添加"…） | **词表来自规则包**（`claim.target` 集），经 `parse_label(claim_words=...)` **参数传入**；解析层不留硬编码词表。判定层在唯一分派点按本轮规则包对齐（不足则重抽），防假 `skipped` |

**字段降级口径（K26）**：有值但无法映射（单位不认识 / 日期非法）一律**丢弃该字段 + 明确原因码**。
"标个非法但仍算已提供"会让存在性规则把它判成 `compliant`——把真实标示缺陷读成合规，
比误报更严重。

### 2.3 工程陷阱（必须处理）

- 全角/半角混用（`≥` / `>=` / `≧`）；
- CRLF 残留 → 统一归一为 `\n`；
- 中文路径与 GBK 控制台编码 → 入口 `_ensure_utf8_stdio()`；
- 数值单位不一致（`%` / `g/100g`）→ 走**同一张别名表**换算。

## 三、规则层（`pflc/rules/`）

### 3.1 规则条目结构

```python
@dataclass(frozen=True)
class Rule:
    rule_id: str
    dimension: str            # "label" | "nutrition" | "claim"
    kind: str                 # 判定方式："presence" | "threshold" | "claim_support"
    target: str               # 判定对象
    # --- 判定参数 ---
    op: str | None            # ">=" | "<=" | "==" | None
    value: Decimal | None     # 限值（数值规则）
    unit: str | None
    applies_if: Dict[str, list] | None   # 适用条件（如 life_stage ∈ ["幼年"]）
    required_support: List[str] | None   # 宣称规则：需要哪些信息支撑
    # --- 双重门控（D2）---
    status: str               # "verified" | "pending"（数值核对状态，唯一门控判定路径）
    clause_status: str        # "verified" | "pending"（条款号核对状态，只管可证性）
    # --- 可溯源 ---
    anchor: Anchor
    effect: str               # "obligation"（无条件义务）| "conditional"（条件触发）
```

### 3.2 规则包与 manifest

```
src/pflc/data/rules/          # 随包（DEC1 = A：数据进包，2026-10-20）
├── ruleset-label.json        # 强制标示项规则（依据：宠物饲料标签规定）
├── ruleset-nutrition.json    # 营养限值规则（依据：GB/T 31216 / 31217）
├── ruleset-claim.json        # 宣称用语规则
└── manifest.json             # 版本锚点 + 验收门槛 + 覆盖登记
```

`manifest.json` 关键字段：

```json
{
  "ruleset_version": "2026.1",
  "files": {"label": "ruleset-label.json", "nutrition": "...", "claim": "..."},
  "thresholds": {"min_accuracy": 0.95, "max_false_positive": 0.0, "max_runtime_sec": 5},
  "coverage": {"nutrition": {"total_rule_factors": null, "sampled_in_truth": null, "sample_list": [], "note": "抽样覆盖、非逐因素穷举"}},
  "sources": [{"doc_id": "...", "url": "...", "captured_at": "...", "sha256": "..."}]
}
```

**纪律**：`thresholds` **必须随 manifest 下发**，基准层只读；缺失 → exit 2（**不得回落代码默认值**，D13）。

### 3.3 门控单点

```python
def effective_ruleset(scope: str, rules_dir: Path) -> list[Rule]:
    """scope ∈ {label, nutrition, claim}；只返回 status=verified 的条目。
    pending 条目在此被拦下，但会通过 pending_rules() 显式呈现。"""
```

- **只有数值 `status` 门控判定路径**；`clause_status=pending` 的条目**仍参与判定**（条款号不影响判定，只影响可证性展示）；
- **CLI 可预览不拦截**（`--preview` 打印 pending 清单）。

## 四、判定引擎（`pflc/engine/`）

### 4.1 三类判定方式

| `kind` | 语义 | 判定逻辑 |
|---|---|---|
| `presence` | **存在性判定**（标示项是否提供） | 字段 `provided` → `compliant`；`not_provided` 且原文无例外情形 → **`noncompliant`**；原文写了不适用情形且本件命中 → `skipped` |
| `threshold` | **阈值判定**（保证值 vs 限值） | 按 `applies_if` 筛适用规则 → `Decimal` 比较 `op`；满足 → `compliant`；不满足 → `noncompliant`；保证值缺失 → `not_provided` |
| `claim_support` | **条件齐备性核查** | 宣称存在 → 检查 `required_support` 列出的信息是否齐备；齐备 → `compliant`；不齐备 → `noncompliant` |

### 4.2 判定语义硬纪律（对应 D1）

```
原文是"应当 X"（无条件义务）→ 缺 X 记 noncompliant        # 绝不记 not_applicable
原文自带"不适用情形" → 才允许 skipped
"没看到材料" → unknown（不是 fail，但计入待人工确认）
一条规则都不适用 → 该维度 not_assessed（绝不输出 compliant）
```

**义务类型分栏**（D 条）：`effect=obligation`（无条件义务）与 `effect=conditional`（条件触发，如"监管部门可以要求"）**分栏呈现**；**频次/计数只取无条件义务栏**。

### 4.3 聚合规则

```
overall =
  "noncompliant"  若任一参与维度有 noncompliant
  "not_assessed"  若全部参与维度均 not_assessed（零适用项）
  "not_provided"  若参与维度仅有 not_provided / unknown 且无 compliant
  "compliant"     仅当所有参与维度至少各有一条 compliant 且无 noncompliant
```

**零生效维度不参与聚合**（D4）：`excluded=True` 的维度不计入 `overall`，报告中保留区块并写明排除理由。

### 4.4 单件与批量共用分派点（D17）

```python
def check_card(card: LabelCard, rules_dir: Path, scope: str = "all") -> CheckResult: ...
def check_file(path: Path, rules_dir: Path) -> CheckResult: ...   # 单件
def scan_dir(dir: Path, rules_dir: Path, baseline: Path | None) -> ScanResult: ...  # 批量
```

`check_file` 与 `scan_dir` **内部都调 `check_card`**——两条通路各写一套分派 = 最隐蔽的口径漂移。

## 五、报告层（`pflc/report/`）

### 5.1 单一渲染源（D 条：结构性质）

```python
def report_sections(result: CheckResult, meta: dict) -> list[Section]:
    """返回结构化章节；Markdown 渲染器与 CSV 渲染器各自读它。
    于是"两格式内容一致"不再是人工比对，而是结构上不可能不一致。"""
```

### 5.2 报告必含四块

1. **输入事实**（标签原文摘要 + 解析到的字段 + `未提供` 清单）；
2. **参数来源块**（每项参数：发布机关 + 文号 + 条款 + URL + 抓取日期）——让读者**不开仓库也能核证**；
3. **逐项判定过程**（直接渲染引擎的 `Finding` 留痕，报告层**不重算**，否则又是一处第二实现）；
4. **适用依据 + 免责声明**。

### 5.3 硬约束

| 约束 | 落地 |
|---|---|
| **溯源完整性** | 导出前断言"溯源表行数 == 明细行数"且每条引用 id 可解析；不满足**报错拒导** |
| **无外链** | 机读产物（CSV）单元格与关系项里不得有 URL——"断网可开"做成**硬断言测试** |
| **逐字节可复现** | 自写最小 writer；产物无时间戳；相同输入两次导出字节一致（守门测试） |
| **"未启用"显式写出** | "本次导出未启用 X（用 --with-check 启用）"而非留空 |
| **免责声明强制** | 每份报告末尾固定块 |

## 七、CLI（`pflc/cli.py`）

| 子命令 | 作用 | 退出码 |
|---|---|---|
| `check <file>` | 单件核验 | 0 无不符合 / 1 检出不符合 / 2 输入错误 |
| `scan <dir> [--baseline f]` | 批量 + 两轮对账 | 0 无新增违规 / 1 有 / 2 用法错误 |
| `bench [--only name]` | 跑基准套件 | 0 达标 / 1 未达标 / 2 用法或未知名 |
| `report <file> --out <dir>` | 导出双轨报告 | 0 成功 / 1 溯源不完整 / 2 输入错误 |
| `diagnostics` | 打印规则/数据状态 | 0 常态 / 1 有 pending / 2 数据缺失 |
| `selftest [--out f]` | 冻结态自检（写文件回传） | 0 通过 / 1 失败 |
| `gui` | 启动桌面应用（**惰性导入**） | 0 正常 / 3 缺依赖 |

**惰性导入纪律**（关键）：`try` 必须包住**从 import 到调用完成**的整条路径，不是只包 import 那一行——分层越严（重件只许在函数体内 import），边界越靠后越易漏。缺依赖走 **exit 3** 而非裸异常。

**入口守卫**：`_ensure_utf8_stdio()` 覆盖**所有会打印的可执行入口**（主 CLI + `tools/` 下每个脚本），不是只守主命令。

## 八、GUI（`pflc/gui/`）

- **多页签**：标签导入 / 标示项检查 / 限值判定 / 宣称核查 / 基准评测 / 关于（免责声明）；
- **只消费编排层 API**，零判定逻辑（AST 门禁三条齐上，D10）；
- **零模态框**：通知走可注入 `notify` 信号；文件对话框只准在按钮槽内；
- **中文字体显式加载**：按候选路径 `QFontDatabase.addApplicationFont()` 再 `QApplication.setFont()`；**字体路径由 `WINDIR`/`SystemRoot` 推导**，不写死绝对盘符（换机失效 + 脱敏审计命中）；
- **offscreen 测试常驻**：`QT_QPA_PLATFORM=offscreen` 必须在**首次导入 PySide6 前**设置；模块级 `pytest.importorskip("PySide6")` 声明式跳过。

## 九、打包（`pflc/packaging.py` + `tools/pflc.spec`）

- **onedir 双 exe**：GUI（`console=False`）+ CLI 控制台（`console=True`）；
- **datas 白名单单一事实源**：只准由 `packaging.build_datas()` 产生；
- **构建后三断言**：dist 全树禁区扫描 + 内嵌数据逐份 sha256 对账 + 白名单外多余检测，任一违反 exit 1；
- **冻结态数据定位** `find_data_dir()` 分支：显式 > 环境变量 > `sys._MEIPASS/data`（PyInstaller 6）→ exe 目录/`_internal/data`（PyInstaller 5 兼容）> CWD 上溯；**自动识别 5.x 平铺与 6.x `_internal/` 两种布局**；
- **冻结态自检断言**：`os.path.commonpath([exe 目录, data 目录]) == exe 目录`（数据必须落在 dist 之内）；非冻结态返回 `None` 而非 FAIL；
- **降级提示分流**：冻结态说"本发行包未内嵌该功能"，源码态才说 pip 安装——**冻结态用户装不上 pip**。
