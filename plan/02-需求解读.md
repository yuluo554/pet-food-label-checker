## 一、痛点 → 能力转译表

| # | 养宠人痛点（真实场景） | 现状（商业侧做法） | 本工具能力 | 判定内核 | 可验证性来源 |
|---|---|---|---|---|---|
| P1 | **标示项易漏**：标签上通用名、成分分析保证值、原料组成、添加剂、净含量、生产者信息等强制标示项是否齐全合规，肉眼逐条对照规定必漏 | "AI 点评配料表"——输出一段话，不可复现、无条款依据 | 把《宠物饲料标签规定》强制标示要求编码为**结构化检查规则**，对标签档案**逐项清单化核验** | 确定性规则引擎（无 LLM） | 合成标签基准：逐项植入"缺项"，比对引擎结论与植入真值 |
| P2 | **限值无从判定**："粗蛋白 ≥26%" 这类保证值到底达没达到国标对应生命阶段的限值，标准正文普通人拿不到也读不懂 | 无对应产品（标准正文不可得） | 把 GB/T 31216—2014（犬粮）/ GB/T 31217—2014（猫粮）营养限值编码为**版本化规则包**，按标签声明的生命阶段逐项判定 | 确定性阈值比较（Decimal） | 合成标签基准：程序化生成"保证值达标/越限"样例，真值对账 |
| P3 | **宣称无据**："天然粮""无谷粮"是受规定约束的限定用语，营销话术是否越界无从判断 | 无对应产品 | 把限定用语的**适用条件**编码为规则，对宣称逐个核查"其适用条件所要求的信息支撑是否齐备" | 条件齐备性结构化核查 | 合成标签基准：植入"宣称无支撑"样例 |

**转译结论**：三条痛点的共同解是**同一件事**——把散在法规与国标里的**可机器判定的条款**抽成规则包，用**确定性引擎**逐项给出**带条款锚点的三态结论**。这决定了架构必须是"规则包 + 判定引擎 + 基准"三段，而不是"调 LLM 出一段点评"。

**为什么 LLM 聊天给不了**：① 无持久条款规则库（每次对话重新"理解"法规，口径漂移）；② 无逐项三态结论（只有一段模糊文字）；③ 无可复现基准（同一输入两次结论可能不同）；④ 无条款锚点（无法核证"依据哪一条"）。

## 二、FR 功能清单（带优先级）

> 优先级定义：**P0 = 首期必达**（M6 发布前必须可用且有证据）；**P1 = 首期尽力**（可达则做，不阻塞发布）；**P2 = 扩展项**（题面明示"不承诺首期交付"，只留接口与目录）。

### P0 — 首期必达

| FR | 名称 | 输入 | 输出 | 验收口径 |
|---|---|---|---|---|
| FR-01 | **标签文本导入器** | 贴文本（标签全文） | `LabelCard` 结构化档案（字段化抽取：通用名/保证值键值对/原料组成/添加剂/净含量/生产者信息/宣称用语/产品类别/生命阶段） | 同一文本 → 同一档案（逐字节一致）；无法解析的字段落 `未提供`，**不得猜测补全** |
| FR-02 | **强制标示项检查引擎** | `LabelCard` + 标签规定规则包 | 逐项三态结论 + 条款锚点 | 每条结论带 `anchor`（公告号 + 文件名 + 条款位置）；未挂原文核对的规则 `status=pending` 不得进入判定路径 |
| FR-03 | **营养限值判定引擎** | `LabelCard` + 营养限值规则包 | 按生命阶段逐项"保证值 vs 限值"判定 + 条款锚点 | 数值口径**一处定义**（规则包）、多处引用；比较全程 `Decimal`；限值 `status=pending` 的维度不参与聚合 |
| FR-04 | **宣称用语核查引擎** | `LabelCard` + 宣称规则包 | 每个宣称"适用条件齐备性"结论 + 条款锚点 | 只做结构化核查（宣称存在 → 条件是否齐备），**不做语义硬判**（配料是否确为"天然"不判） |
| FR-05 | **合成标签基准** | 固定 seed | 合规/违规合成标签样例 + 植入真值 + 四套件评测报告 | **一条命令复现**；零外部依赖、零 API；指标口径进 README |
| FR-06 | **CLI 端到端** | 标签文本文件 | 判定结论（人读 + 机读） | 退出码三语义锁进测试（0 达标 / 1 未达标或检出不符合 / 2 输入或用法错误） |
| FR-07 | **报告导出（双轨）** | 判定结果 | Markdown（人读）+ CSV（机读） | **单一渲染源**使"两格式内容一致"成为结构性质；机读产物**逐字节可复现**；**无外链**；溯源完整性硬约束（不留半溯源）；"未启用"章节显式写出 |
| FR-08 | **桌面 GUI** | 用户粘贴标签文本 | 多页签结果展示 | **零判定逻辑**（AST 静态门禁三条齐上：不 import 规则层 + 无算术 `BinOp` + 无政策数值字面量）；只消费编排层公开函数 |
| FR-09 | **exe 打包** | 源码 | PyInstaller onedir 双 exe（GUI `console=False` + CLI `console=True`） | 冻结态 `--selftest <out>` 断言 `frozen=true` + 数据目录落在 exe 目录内 + 规则数 > 0；构建后白名单/禁区双断言 |

### P1 — 首期尽力

| FR | 名称 | 说明 |
|---|---|---|
| FR-10 | **批量扫描 + 两轮对账** | `scan --baseline`：新增违规 / 已修复 / 持续违规 / 稳定 四类集；配对主键 = **稳定身份键**（`card:<card_id>`），不用内容指纹 |
| FR-11 | **溯源完整性硬约束** | 导出前断言"溯源表行数 == 明细行数"，每条引用 id 可解析；不满足即报错拒导 |
| FR-12 | **演示物料程序化产出** | `tools/make_demo_assets.py` 产 PNG 截图 + GIF（offscreen + 显式中文字体），入仓 `docs/demo/` |

### P2 — 扩展项（题面明示不承诺首期）

| FR | 名称 | 前提条件 |
|---|---|---|
| FR-E1 | AAFCO / FEDIAF 横向对照 | 官方数值表**付费**不可直连 → 人工整理 JSON + 逐条注来源，不承诺官方数值全表 |

## 三、边界与非目标（防 scope 失控）

### 3.1 明确不做

- **不做**喂食建议与营养配方推荐（不给"每天喂多少克"）；
- **不做**健康诊断、疾病与过敏判断——**兽医免责红线**：输出不构成兽医意见，宠物健康问题以执业兽医意见为准；
- **不做**电商比价与导购；
- **不对接**监管申报接口；
- 首期**不做**图片 OCR 与多语言标签。

### 3.2 合规红线（硬约束，不可协商）

| 红线 | 落地方式 |
|---|---|
| **全本地处理存储、零上传** | 无任何网络调用；无 API key；核心层零第三方依赖；基准可断网跑 |
| **免责声明强制** | 输出为基于法规条款与国标限值的**合规检查发现**，不构成产品合格判定、检测结论或行政认定；正式结论以具备资质的检验检测机构报告与主管部门口径为准；报告与 GUI 均显式呈现 |
| **未挂原文核对不得生效** | 规则条目 `status=pending` 时引擎拒绝其进入判定路径（门控单点：`effective_ruleset()`）；CLI 可预览但不拦截 |
| **演示与基准一律合成标签** | **假品牌名白名单**（"测试粮A/B"等）统一登记；禁止真实品牌标签入库为基准样例 |
| **真值样例严格隔离** | 引用 Royal Canin / Orijen 公开实测保证值仅作录入核对参照，记抓取日期与来源 URL，**不入基准真值库** |

### 3.3 数据纪律

- **数值规则条数不预设硬数字**：以全文录入逐条核对后的条目为准（题面与规则包一律不写硬数字）；
- **数值口径一处定义、多处引用**：限值数值只存在于规则包一处，判定/报告/基准全部引用规则包——**零政策字面量门禁**扫描引擎/基准/CLI/GUI 源码（含 docstring 与注释）；
- **规则包是冻结产物**：禁手改，改需求走生成器整目录重生成，配"再生成逐字节一致"守门测试。

### 3.4 品牌隔离

- 不复制姊妹项目代码；
- 公开文档**不提**其余项目业务领域（提及系列时一律用"方向级描述"，不落行业具体名词）。

## 四、用户旅程（首期主路径）

```
养宠人 / 从业者
   │
   ├─ ① 从产品包装或电商页复制标签全文
   │
   ├─ ② 打开桌面应用（或 CLI）→ 粘贴到"标签导入"页签
   │
   ├─ ③ 点击"核验"
   │      ├─ 解析层：文本 → LabelCard（缺失字段标"未提供"）
   │      ├─ 强制标示项检查：逐项 符合/不符合/未提供 + 条款锚点
   │      ├─ 营养限值判定：按生命阶段，保证值 vs 国标限值
   │      └─ 宣称用语核查：宣称 → 适用条件齐备性
   │
   ├─ ④ 查看结果：分级清单 + 每条挂条款依据 + 免责声明
   │
   └─ ⑤ 导出报告（Markdown 人读 / CSV 机读）或直接阅读
```

**从业者自查路径**：批量扫描一目录标签文件 → `scan` → 两轮对账（本次 vs 上次基线）→ 看"新增违规 / 已修复 / 持续违规"。

## 五、验收口径（与评分标准对齐）

| 评分维度（题面 §四） | 分 | 本项目对应交付物 | 验证方式 |

| 功能实现效果 | 40 | 标示项检查正确性、营养限值判定正确性、宣称核查准确率、合成基准达标率、条款锚点可溯源率 | 基准四套件 + 溯源完整性断言 + 锚点可解析率 |

| 技术创新性 | 20 | 规则引擎化、三态判定框架、数值口径一处定义、合成标签可复现评测 | 架构文档 + 零字面量门禁 + 位级一致守门 |
| 综合表现力 | 20 | 技术报告、README（GIF 演示）、打包质量、测试与 CI | 测试全绿 + CI 四矩阵 + Release 附件 |
