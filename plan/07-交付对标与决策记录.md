| **2026-10-15（M3）** | 🔴 **M4 核对发现：`overall` 套件无探活 = 永绿门（交接漏报）** | M3 收尾逐条核对 M4 DoD 时**实测**：四套件只有 `detection`/`boundary`/`traceability` 有探活，**`overall` 没有**。变异证明：把 `run_overall` 的比较改恒真（`if True:`）或把 `passed` 改成恒 `True` → **231 项测试全绿**；同样手法改 `run_boundary` 的 `passed` → **立刻 1 项失败**（对照组证明变异手法本身有效）。→ **`overall` 的达标判定当前不可证伪**。这直接违反 M4 DoD"每套件配探活"与 K14。**教训**：门禁"有测试"不等于"测试有效"——**每个门都要做变异验证，并留一个已知有效的对照组**（防"变异根本没生效"造成误判） |

| **2026-10-15（M4）** | **两次踩到"假门"并当场修掉（本棒最重要的一条）** | ① CI 门 `test_ci_runs_every_frozen_generator_check` 首版用**子串匹配**——把 `gen_cases.py --check` 整段注释掉仍绿；② README 指标门首版用**全文件子串匹配**——把 `accuracy=1.0` 手改成 `0.9` 仍绿（别处还有别的 `1.0`）。两处都**只有靠变异验证才暴露**。修法：判据落在**结构位置**上（解析 workflow 的 run 步骤 / 定位"实测指标"小节再**行内**逐项核对）。**"文件里出现过这串字"是最容易写出的假门**——它验的是文档排版，不是事实 |
| **2026-10-15（M4）** | **源码态绿 ≠ 发行态绿：冻结真值库必须随包** | GUI 与 CLI 都带基准功能，期望来源是入库真值库。若不进 `DATA_WHITELIST`，发行态只能回落现场重算——源码态 `truth_source=frozen`、发行态悄悄变成 `regenerated`。**这是"同一个功能在两种运行形态下名不副实"**，与 K21（数据必须随包走）同一族。故把 `benchmark` 收进白名单并配守门测试 |
| **2026-10-15（M4）** | **覆盖登记不能由"写 manifest 的脚本"自己编** | `gen_rulesets.py` 原先只读条文块、不读真值库，无法回填采样数。本棒改为在 `generate()` 内**先由规则包生成真值库、再从真值库实算覆盖**（规则包 → 真值库 → 回填 coverage → 重冻结 manifest）。**顺序约束用代码固化，而不是靠人记得按顺序跑**——手写清单必然漂移（plan/05 §4.5 的判别正是"只写分子不写分母就是假覆盖"，同理"分子是手搓的就是假数"） |

## 五、诚实口径（DoD 措辞纪律）

| 情形 | 允许的措辞 | 禁止的措辞 |
|---|---|---|

## 六、反模式清单（本项目明令禁止）

| 反模式 | 为什么禁止 |
|---|---|
| 把建仓推迟到发布里程碑 | 把全项目 CI 首跑风险压进发布窗口；"本地全绿"绝不是"CI 绿"的代理 |
| DoD 里写"CI 绿"而无远端 | 诚实性硬伤——同一对话内自相矛盾 |
| 审计命令接管道 | `审计 \| tail` 吞掉 FAIL 退出码；`cmd \| tail` 取到 `tail` 的 `$?` |
| 留档文档复述敏感字面值 | 自命中，必跑第二轮历史重写 |
| 为凑覆盖率造假规则/假用例 | 假覆盖比不覆盖更危险 |
| 基准的达标分支不看分母为 0 | `hits(0) <= max(0)` 恒真 = 假门 |
| 手抄标准数值表 | 不可复现的转写漂移且无法复核 |
| 把"解析不到"当"合规"或"违规" | 违反"没查出问题 ≠ 没检查过" |
| 把"没做"记成"不用做" | 合规结论虚高，比误报更严重 |
