## 五、诚实口径（DoD 措辞纪律）

| 情形 | 允许的措辞 | 禁止的措辞 |
|---|---|---|
| 无远端、未跑 CI | "**本地等价校验通过**（未接远端，CI 待首推验证）" | "CI 绿"、"CI 三矩阵通过" |
| 计划要做但未执行 | "⬜ 待办" | 打勾 |
| 首跑失败 | **照录 run id + 失败面 + 根因**；修复后写"CI 绿（首跑修复后）" | 抹除失败记录 |
| 用户未答复的确认项 | "未获明确答复，按推荐默认执行（可事后调整）" | "用户已确认" |
| 未实际验证的"可复现" | "⬜ 未实测" | "应当可复现" |

**"本地等价校验"的完备形态**：不是一句话，而是一组**可指认的替代证据**——本机可实跑的通路逐条跑（pytest 全量 / 生成器 `--check` / 扫描器 selftest / bench 套件 / 冻结态验收），**不可本机实跑的通路显式标注"待首推验证"**。

## 六、反模式清单（本项目明令禁止）

| 反模式 | 为什么禁止 |
|---|---|
| 把建仓推迟到发布里程碑 | 把全项目 CI 首跑风险压进发布窗口；"本地全绿"绝不是"CI 绿"的代理 |
| DoD 里写"CI 绿"而无远端 | 诚实性硬伤——同一对话内自相矛盾 |
| 审计命令接管道 | `审计 \| tail` 吞掉 FAIL 退出码；`cmd \| tail` 取到 `tail` 的 `$?` |
| 留档文档复述敏感字面值 | 自命中，必跑第二轮历史重写 |
| 为凑覆盖率造假规则/假用例 | 假覆盖比不覆盖更危险 |
| 基准的达标分支不看分母为 0 | `hits(0) <= max(0)` 恒真 = 假门 |
| 手抄标准数值表 | 不可复现的转写漂移且无法复核 |
| 把"解析不到"当"合规"或"违规" | 违反"没查出问题 ≠ 没检查过" |
| 把"没做"记成"不用做" | 合规结论虚高，比误报更严重 |
| GUI 层写判定逻辑 | 产生第二份实现，口径必然漂移 |
| 在仓库树内跑冻结态验收 | CWD 上溯会命中仓库 data，"内嵌数据"验了个寂寞 |
| 发布附件用中文名 | `gh release create` 在 Git Bash 下剥中文附件名 |
| 里程碑收尾不写 HANDOFF | 实测必然漏——K 口径/环境坑/DoD 证据只存在于当下对话的工作记忆 |
| 计划文档里写姊妹项目的**领域具体名词** | 计划期图省事的每个具体词都是发布期的潜在改写点；一律用"方向级描述" |
