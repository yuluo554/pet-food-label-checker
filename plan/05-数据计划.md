## 一、数据先行原则

**数据拿不到 = 题做不成**。本项目数据底座的三条支柱与各自的可获取性：

| 支柱 | 内容 | 可获取性 | 处理路径 |
|---|---|---|---|
| **A. 法规层**（强制标示项 + 宣称用语） | 《宠物饲料标签规定》（农业农村部公告第 20 号附件 3） | ✅ **M1 已获取**（FAO 库扫描件 + feed-china 转载交叉校验）；官方页可达但附件为 `.ceb` 打包件 | 两条独立来源入仓 `data/knowledge/raw/`，逐条挂条款核对后转 `verified`；来源如实标注 |
| **B. 标准层**（营养限值） | GB/T 31216—2014《全价宠物食品 犬粮》/ GB/T 31217—2014《猫粮》 | ✅ **M1 已获取**（瓦片精灵图旁路 + 逐格 OCR；检索页 ✅ 现行无迭代） | 数值表逐条挂条款核对后转 `verified`；**未核对前一律 `pending`，门控拦下** |
| **C. 过渡规则层**（版本对照） | 农业农村部公告第 210 号（2019-09-02，标签过渡期延长） | ✅ 权威转载源可读 | 入仓作版本对照依据；三态对照包留扩展 |

**未核对不得生效**：规则包条目一律 `status=pending` 起步，只有逐条挂原文核对通过才转 `verified`；引擎门控拒绝 pending 条目进入判定路径。

**M1 结果**：A/B 两支柱**均已获取并核对**——规则包 45 条，其中 43 条 `verified`、2 条 `pending`
（牛磺酸：限值随水分形态分支、当前门控键表达不了，属"宁缺勿造"的正常落地）。

## 二、`data/` 目录结构

```
data/

├── knowledge/
│   ├── raw/                  # 官方/权威原文快照（.gitattributes 标 -text 防 EOL 改写）
│   │   ├── moa-20-2018/      # 20 号公告 + 附件
│   │   └── moa-210-2019/     # 210 号公告
│   └── clauses/              # 条文块索引（按条款号切块，供锚点解析）
├── rules/                    # 版本化规则包（生成器产出，禁手改）
│   ├── ruleset-label.json
│   ├── ruleset-nutrition.json
│   ├── ruleset-claim.json
│   └── manifest.json
├── samples/                  # README 可跑输入夹具（生成器产出，纳入位级一致守门）
│   ├── label-demo-ok.txt
│   ├── label-demo-missing.txt
│   └── label-demo-overlimit.txt
└── benchmark/                # 合成标签样例 + 植入真值（字节冻结 fixtures）
    ├── cases.json            # 样例 + expect（真值）
    └── brand-whitelist.json  # 假品牌名白名单
```

**`.gitattributes` 两半**：`* text=auto eol=lf` 管住源码行尾；**被台账登记过 sha256 的快照**（官方 PDF/文本）必须标 **`-text`**（连同 `*.pdf binary`），否则克隆时字节被归一化、sha256 失配。验证手段 = **克隆后比对快照实际 sha256 与仓库值**（`git status` 看不出来）。

## 三、规则包形态（版本化冻结数据集）

### 3.1 为什么是"冻结产物"

规则包一旦冻结就是**基准的可信锚**。若可手改，则"引擎对不对"永远无法与"数据对不对"分离。纪律：

- **禁手改**：改需求 → 走生成器 `tools/gen_rulesets.py` 整目录重生成；
- **配"再生成逐字节一致"守门测试**：`gen_rulesets.py --check` 输出 `FROZEN_RULESET_OK`；
- **产物无时间戳**：两次运行/构建**逐字节一致**。

### 3.2 生成器设计

```
tools/gen_rulesets.py
  输入：data/knowledge/clauses/*.json（人工/脚本录入的条文块 + 数值）
  输出：data/rules/ruleset-{label,nutrition,claim}.json + manifest.json
  模式：--force（重生成） / --check（位级一致校验）
```

**生成器内嵌的三条确定性纪律**：
1. **禁 stdlib `random`、禁 set 迭代序、禁系统时钟** —— 用自研确定性 RNG（splitmix64）或纯排序遍历；
2. **落盘产物无时间戳**；
3. **JSON 序列化固定**：`sort_keys=True`、`ensure_ascii=False`、`indent=2`、`newline="\n"`（用 `open(..., newline="\n")` 而非 `Path.write_text(newline=)`——后者是 3.10+ 参数，3.8 不可用）。

### 3.3 规则条目（双门控）

每条规则挂**两个独立状态**（`plan/03` D2）：

```json
{
  "rule_id": "LABEL-001",
  "dimension": "label",
  "kind": "presence",
  "target": "通用名",
  "effect": "obligation",
  "status": "pending",
  "clause_status": "pending",
  "anchor": {
    "doc_id": "MOA-20-2018-ANNEX3",
    "doc_title": "宠物饲料标签规定",
    "clause": "<待录入>",
    "excerpt": "<待录入>",
    "source_url": "https://law.foodmate.net/show-194580.html",
    "captured_at": "2026-10-15",
    "sha256": "<快照 sha256>"
  }
}
```

**只有 `status` 门控判定路径**；`clause_status` 只管可证性展示。两个状态都在产物/报告**显式可见**。

### 3.4 数值口径一处定义

限值数值**只存在于 `ruleset-nutrition.json`**。判定、报告、基准全部引用规则包。
转录规格（"哪条规则取哪处原文"）作为**数据**放在 `data/knowledge/transcription/spec.json`，
由 `tools/transcribe_clauses.py` 读取——**不内联在脚本里**（脚本内联政策数值
等于在代码里留第二份真相，且会被零字面量门禁正当拦下）。

**零政策字面量门禁**：把全部规则包数值收编为**禁用 token**（运行时从规则包实算，**不是代码字面量**），对**引擎/基准/CLI/GUI 源码**做扫描，**连 docstring 与注释一起扫**。

**豁免口径（M1 勘误，重要）**：
- **整数形态且绝对值 < 20** → 视为结构性常数（下标/计数/短文本长度），豁免；
- **非整数一律不豁免**；
- **必须配"真实规则包下 token 集非空"的守门测试**——豁免口径只在空集上"看起来没问题"
  是不够的。

**为什么改**：M0 写的是"绝对值 < 100 豁免"。那时规则包是空的，看不出问题；
M1 录入真实国标后，**全部百分比限值落在 0.09–28 区间，被该口径整包放过**，
`banned_numeric_tokens` 返回空集 → **门禁完全空转（假门）**。
本项目的政策数值天然是小于一百的百分数，"按大小豁免"与"零政策字面量"这个目标
**在数学上不相容**；正确的判别量是**这个数出现在哪里**，而不是它多大。
改口径后真实规则包下 token 集非空（11 个），且注入测试能被命中。

### 3.5 数值基准（M1 新增）

GB/T 31216/31217 的理化指标表头写明 **"指标（以干物质计）/%"**，而标签保证值是
**按标示状态（as-fed）**给的。**两者基准不同，直接比会造假结论**。

- 规则条目带 `basis` 字段（`dry_matter` / `as_fed`）；
- 引擎对 `basis=dry_matter` 先做 `干基值 = 标示值 / (1 - 水分% / 100)` 再比；
- **水分未标示 → 记 `unknown` + 原因码 `basis_undetermined`**，绝不拿未换算的值比、绝不猜水分；
- 换算过程写进结论 `note`，报告里可见。

## 四、合成标签基准（核心资产）

### 4.1 为什么程序化自制

解决"没有标注数据"的死结：**随机生成输入 + 真值 JSON**，固定 seed 可复现，评测零成本重复。

### 4.2 真值语义（一次定清）

每个样例的 `expect` 记录：

| 字段 | 语义 |
|---|---|
| `expected_overall` | 主期望（整体结论） |
| `expected_findings` | 逐规则期望结论（`rule_id → verdict`） |
| `also_expect` | **同一注入隐含的其余结论**（如"缺净含量"还隐含"溯源表应有该条 noncompliant"） |
| `injected` | 植入了什么缺陷（人类可读，供审计） |

**对账语义收成单一实现源**（`benchmark/cases.py` 的 `observed_nonpass()` / `compare_nonpass()`），真值库测试与基准**共用**同一函数——否则"基准说达标、测试说不过"的双口径漂移。

### 4.3 四类植入（逐类可辨）

| 类 | 植入内容 | 期望检出 |
|---|---|---|
| **合规样例** | 全部强制项齐备 + 保证值达标 + 宣称有支撑 | 全 `compliant` |
| **缺项样例** | 逐项植入缺失（缺净含量 / 缺生产者 / 缺保证值…） | 对应项 `noncompliant`，其余 `compliant` |
| **越限样例** | 保证值低于国标对应生命阶段限值 | 对应指标 `noncompliant` |
| **宣称无支撑样例** | 宣称"天然/无谷"但缺少其适用条件要求的信息 | 对应宣称 `noncompliant` |

### 4.4 假品牌名白名单

```json
{
  "allowed": ["测试粮A", "测试粮B", "测试粮C", "测试粮D"],
  "forbidden_note": "禁止真实品牌名入库为基准样例；白名单外品牌名生成器直接报错退出"
}
```

**生成器硬断言**：产出的品牌名必须命中白名单，否则 exit 1。

### 4.5 覆盖登记（防"假覆盖"）

`manifest.json` 的 `coverage` 逐形态登记 **"规则包因素总数 / 真值库采样数 / 采样清单"** 并声明"抽样覆盖、非逐因素穷举"。

**判别**：只写分子（采样数）不写分母（总数）就是假覆盖。

### 4.6 与真值样例的隔离

Royal Canin / Orijen 公开实测保证值**仅作录入核对参照**，记抓取日期与来源 URL，**不入基准真值库**——两者严格隔离，避免真实品牌数据污染合成基准。

## 五、数据台账纪律（`data/README.md`）

台账必须逐条登记：

| 登记项 | 说明 |
|---|---|
| 来源 | 官方 / 权威转载（如实标注），URL |
| 许可 | 公开可引用 / 转载 |
| 三态 | ✅ 已实测可获取 / ⬜ 未核实或不可直连 |
| 抓取日期 | 基准日 |
| sha256 | 入仓快照的哈希（可证性） |
| status | `verified` / `pending`（未核对不得生效） |

**每份数据登记来源与许可**；无出处的值**不得以确定语气落库或写进结论**。

### 6.2 M1 实录：两处"看似不可得"实际都拿到了

**① 标签规定全文：字形转曲线 ≠ 数据不可得**

- 20 号公告附件包 PDF（`file2.foodmate.net/...hll201902121526.pdf`，25,331,751 字节 / 95 页）
  经 `pdftotext` 提取汉字数 **0**、`pdffonts` 无字体、`pdfimages` 无位图
  → Foxit 打印驱动**字形转曲线**，该文件确实不可提取；
- **但同一份内容换个来源就有文本层**：FAO FAOLEX 库
  `https://faolex.fao.org/docs/pdf/chn176389.pdf`（7,843,144 字节 / 34 页 / `%PDF-1.6`）
  含 `HiddenHorzOCR` CID 字体（Adobe Paper Capture 隐藏 OCR 层）
  → `pdftotext -enc UTF-8 -layout` 提取汉字 **10,858** 个，**26 条 + 附录 1–9** 完整；
- 另取 feed-china 转载正文（`https://www.feed-china.cn/wap/industrytrends/1865.html`）
  交叉校验——**两源条款编号序列一致**，条款号核对成立。

**② GB/T 数值表：瓦片精灵图旁路 + 逐格 OCR**

1. 检索可直连：`https://std.samr.gov.cn/gb/search/gbQueryPage?searchText=GB%2FT%2031216&pageSize=10&pageNumber=1` 返回 JSON；
2. 预览页 `showGb?type=online&hcno=...` **带 `Referer`（指向 `newGbInfo`）+ `JSESSIONID` 可直连**，
   HTML 里每个 `<div class="page" bg="...">` 给出该页精灵图令牌；
3. 瓦片图在 `viewGbImg?fileName=<bg>`，返回 `image/webp`；**同一 cookie 会话连续请求只有第一个成功**
   → **每张精灵图新建独立会话**；
4. 取回 webp（如 2320×8528）按 span 的 class 行列 + `background-position` 偏移**切片拼回整页**；
5. **整页 OCR 读不出表格数值**（表格线被当笔画、`≥` 被识别成 `之`/`ss`）
   → 必须**按长直线定位网格、抹掉网格线、逐格 `tesseract --psm 7`**；
6. **页图与 OCR 结果同时入仓**：人可核对原始页，机器可核对 OCR 结果。

**结论**：**"JS 增强页取不到载荷" ≠ "数据不可得"**；**"PDF 有页数" ≠ "能提取文字"**。
两条都在 M1 被证伪为"换个渠道/换个方法就能拿到"。

### 6.3 渠道坑实录

- Git Bash 的 `/tmp` 与 Windows Python 路径不通 → 临时文件一律用**工作区相对路径** `.tmp/`；
- 大文件同步 curl 超时 → `-C -` 断点续传 + 后台任务；
- `pdfimages -list` 在字形转曲线 PDF 上返回 0 行 → **入库前必须实测汉字数**；
- **同一 cookie 会话连续请求精灵图只有第一个成功** → 每张新建独立会话；
- **整页 OCR 读不出表格数值** → 按网格切格逐格 OCR；
- `law.foodmate.net` 的 `search.php` 页面是 GBK，**关键词须按 GBK 编码**（直接传 UTF-8 搜不到）；
- `pdftotext -layout` 输出的表格会串行，**文字页可靠、表格页不可靠**——数值表一律走 OCR 路线。
