## M1 · 数据先行（关键里程碑）

**目标**：把"法规条款 + 国标限值"变成**已核对、可生效**的规则包。

**为什么是第一优先**：规则包是判定引擎的输入；没有已核对的数据，引擎再多代码也判不出可信结论。且国标全文机器直连拿不到，**数据获取本身有不确定性**——必须先攻坚。

**任务**

1. 官方/权威全文快照入仓 `data/knowledge/raw/`（`.gitattributes` 标 `-text`）+ 双 sha256 登记；
2. 写**转录器**（脚本转写，**禁手抄**）：按条款号索引解析，**每一处抽取值断言原文逐字包含**；
3. 《宠物饲料标签规定》强制标示项条款逐条挂核对 → `status=verified` + `clause_status=verified`；
4. **GB/T 31216/31217 数值表**：浏览器会话录入（先试页图精灵图/瓦片直连旁路）→ 逐条挂条款核对；
5. 宣称用语条款核对；
6. `tools/gen_rulesets.py` 产三份规则包 + manifest（含门槛下发 + 覆盖登记）。

**DoD**

- [ ] 快照入仓且 `-text`，双 sha256 台账登记；克隆后 sha256 实测一致
- [ ] 转录器"原文逐字包含断言"通过（0 问题）
- [ ] `status=verified` 条目数 > 0，且每条带可解析的条款锚点
- [ ] `gen_rulesets.py --check` 输出 `FROZEN_RULESET_OK`（位级一致）
- [ ] `pflc diagnostics` 显示 verified/pending 计数与 pending 清单
- [ ] **M0 骨架对规则的猜测已被 M1 实测勘误**（枚举/范围/决策记录三处同步）
- [ ] `plan/HANDOFF-M2.md` 已落盘并 commit

**风险与降级**：若 GB/T 31216/31217 全文最终不可得 → 营养限值维度规则全 `pending` → 该维度 `dimension_excluded`（原因码 `no_effective_rules`），报告显式写明"本次未参与聚合"；**绝不编造数值**。此路径下 M3-M4 仍可对标签规定 + 宣称两维度完整交付。

## 每周可演示的验证命令

```bash
# 状态与规则概览
pflc diagnostics

# 单件核验
pflc check data/samples/label-demo-missing.txt

# 基准四套件
pflc bench

# 导出报告
pflc report data/samples/label-demo-ok.txt --out output/

# 冻结态自检（打包后）
pflc.exe --selftest output/selftest.json
```
