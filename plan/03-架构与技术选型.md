## 二、技术选型

| 项 | 选型 | 理由 | 被否方案与原因 |
|---|---|---|---|
| 语言 | Python **3.8+**（本机 3.8.8 / 3.12.10 双通道） | 沿用系列惯例；老解释器上 PySide6 有实测可解析上限 | — |
| 判定内核 | **纯标准库**（`re` / `json` / `decimal` / `dataclasses`） | 零第三方依赖 = 零安装面风险 + 基准可离线跑 + 冻结打包体积小 | 引 pydantic（重、3.8 上限问题、判定层不需要） |
| 数值类型 | **`Decimal`**（`json.load(parse_float=Decimal)`） | 限值判定要检出边界差异，float 尾差不可接受 | float（尾差不可接受） |
| GUI | **PySide6**（6.6.3.1，3.8 实测可解析最高版） | 沿用系列惯例；多页签够用 | Tkinter（观感差）；Web（题面要桌面 exe） |
| 打包 | **PyInstaller onedir 双 exe**；GUI 必须 **≥6** | 5.13.2 扫 PySide6 字节码确定性崩（`Instruction object is not iterable`） | onefile（启动慢、杀软误报高） |
| CLI | 标准库 `argparse` | 零依赖；退出码语义可控 | click/typer（多一个依赖） |
| 测试 | `pytest`（dev extra） | 沿用系列惯例 | unittest（生态弱） |
| 报告 | **自写最小 writer**（Markdown 文本 + CSV） | 逐字节可复现；引第三方（openpyxl 等）会注入时间戳破坏字节确定性 | openpyxl（ZIP 元数据时间戳漂移） |
| 合成数据 | **自研 splitmix64 确定性 RNG** | stdlib `random` 不承诺跨版本序列一致 | `random.Random(seed)`（跨版本不保证） |
| LLM | **不使用** | 纯确定性规则 + 结构化输入，无解析兜底需求 | 见 §四 |
| CI | GitHub Actions，**四矩阵**（windows×{3.8,3.12} + ubuntu×{3.12}） | 老解释器只在 windows 守；ubuntu 守 Linux 通路 | 单矩阵（漏平台差异） |

## 三、关键设计决策（"动了会打挂基准"级口径）

> 以下每条都是**既定口径**：后续任何改动先对照本表，改完必须重跑基准确认不回退。

### D1 · 三态判定框架

结论只允许三态：`compliant`（符合）/ `noncompliant`（不符合）/ `not_provided`（未提供）。

**两种"非结论"必须可区分**（合规类工具最容易被攻击的假合规点）：

| 状态 | 语义 | 判据 |
|---|---|---|
| `skipped` | **不适用**——原文明确写了例外情形，本件不适用 | 只给"原文写了不适用情形"的项；**绝不用于"缺材料/用户没做"** |
| `unknown` | **未观测**——"没看到"而非"缺失" | 不计违规，但计入"待人工确认" |

**硬纪律**：
- **无条件义务缺失 = `noncompliant`**（原文写"应当标示 X" → 缺 X 记不符合）。**"没做"绝不记成"不用做"**（否则合规结论虚高）；
- **一条规则都不适用 → 维度级 `not_assessed`（未评估），绝不输出成 `compliant`**；
- `not_applicable` 分支只保留给"原文明确写了例外情形"的项。

### D2 · 双重门控拆分（数值门 vs 条款门）

每条规则挂**两个独立状态**：

| 字段 | 语义 | 作用 |
|---|---|---|
| `status` | **数值**核对状态（`verified` / `pending`） | **唯一门控判定路径**的开关 |
| `clause_status` | **条款号**核对状态（`verified` / `pending`） | 只管可证性展示，不阻断判定 |

**理由**：耦合成单一 status 的两个失败方向——① 条款号核不到 → 已核对数值也被无谓阻断；② 只看数值 → "条款号没核对却看起来已核对"的风险。两个状态都在产物/报告**显式可见**（"未启用清单"打印 pending 条目）。

### D3 · 门控按计算路径分作用域

`effective_ruleset(scope)` 的 `scope ∈ {label, nutrition, claim}`，各只校验自己引用的条目。**不用"整包全 verified"当唯一门**——否则与某路径无关的 pending 会阻断整条路径。

### D4 · 零生效规则的维度不参与聚合

**维度参与聚合的判据 = 该维度对这份输入有 ≥1 条生效规则且标准已生效**。不参与的维度在结果里显式记录 `dimension_excluded` + 原因码，报告保留该维度区块并写明"本次未参与聚合：零生效规则"。

**理由**：把零生效维度塞进跨维度聚合，会把整体结论无谓拉成"未评估"（假性降级），或拿"尚未生效"的限值判违规（假性违规）。

### D5 · 数值口径一处定义、多处引用（零政策字面量门禁）

限值数值**只存在于规则包**一处。把全部规则包数值收编为**禁用 token**，对**引擎/基准/CLI/GUI 源码**做扫描，**连 docstring 与注释一起扫**。数值只能来自规则包——杜绝"抄进代码的第二份真相"。

转录规格（"哪条规则取哪处原文"）也作为**数据**放在 `data/knowledge/transcription/spec.json`，
**不内联在脚本里**：脚本内联政策数值等于在代码里留第二份真相，且会被本门禁正当拦下。

**豁免口径（M1 勘误）**：**整数形态且 < 20** 才豁免（下标/计数/短文本长度）；
**非整数一律不豁免**。原口径"绝对值 < 100"在真实数据下使门禁**完全空转**——
本项目的政策数值天然是小于一百的百分数，全部被整包放过，`banned_numeric_tokens` 返回空集。
故**豁免口径必须配"真实规则包下 token 集非空"的守门测试**，只在空集上"看起来没问题"不够。

### D5b · 数值基准必须显式（干物质 vs 标示状态）

GB/T 31216/31217 的理化指标表头写明 **"指标（以干物质计）/%"**，而标签保证值是
**按标示状态（as-fed）**给的。**两者基准不同，直接比会造假结论**（高水分湿粮的标示值
换算到干基后显著变大，直接比会误判为不符合）。规则条目带 `basis` 字段；
引擎对 `basis=dry_matter` 先换算再比；**缺换算所需字段 → 记 `unknown` + 原因码**，
绝不直接比、绝不猜。**这是"宁可不判，也不造假结论"在数值层的落地**。

### D6 · 规则包是冻结产物，禁手改

改需求 → 走生成器整目录重生成 → 配"再生成逐字节一致"守门测试（`gen_rulesets.py --check` 输出 `FROZEN_RULESET_OK`）。

**字节冻结分层设防**：文本行尾（`.gitattributes` `eol=lf` + CR 守门测试）**与** zip 容器/压缩流（若有）各自有守门测试。**CR 门禁按扩展名豁免二进制件**（PNG/PDF 的 0x0D 是合法内容字节），且豁免本身配非空转守门测试。

### D7 · 溯源完整性硬约束，不留"半溯源"

交付物里每条结论/数值都必须能追到规则条目。**导出前断言**："溯源表行数 == 明细行数"且"每条引用 id 可解析"，不满足即报错拒导。**理由**：核证类交付物里，"半溯源"比"无溯源"更危险（读者以为已可核证）。

### D8 · "未启用"章节显式写出

报告里"本次导出未启用 X"必须显式写出，**不留空**——**"没查"与"查了没问题"是两种截然不同的结论**，留空会被误读成后者。

### D9 · 编排上收成公开函数组，行为等价靠三方对账

CLI 与 GUI 共用 `pcl.pipeline` 的公开函数。测试断言**行为一致**（CLI stdout 的结论 == 直接调 pipeline 的字段 == 报告章节里的结论），**不是** `assert "pipeline" in source` 这种字面声明。

### D10 · GUI 零判定逻辑靠静态门禁（三条齐上）

AST 断言：① 不 import 规则层/引擎内部模块；② **无算术运算 `BinOp`**（`*` `/` `-` `//` `%` `**` 且两侧操作数均非字符串字面量——字符串 `*`/`+` 是排版不算）；③ **无政策数值字面量**（与引擎侧同一份 `BANNED_TOKENS`）。

只守 import 面会漏掉"界面里直接算"与"界面里内联政策值"两种绕过。

### D11 · 基准分"样本驱动"与"规则驱动"两层

① **样本驱动**（真值库全量重算对账）证明"引擎在这些样本上对"，但样本没覆盖的端点它证明不了；② **规则驱动**（不读真值库，只从规则表推导切换端点，做 ±精度邻域断言）证明"引擎在*所有*有限端点上对"。

**每套件配探活测试**（注入缺陷 → 基准必须报未达标），且**期望必须有独立来源**（锚定冻结真值库，不与引擎共用通路，否则探活是永绿门）。

### D12 · "未启用"套件不冒充通过（空分母防空）

误报对照零样本时 `hits(0) <= max(0)` 恒真 = 假门。正解 = 空分母分支统一 `not_enabled=true` + notes 写明"该类用例未生成" + **exit 1**；分母为 0 的准确率按 0 计必未达标；探活测试锁死。

### D13 · 验收门槛随 manifest 下发（数据非代码）

基准的验收门槛（达成率/误报率上限）随规则包 manifest 下发，基准层**只读**，缺失即报配置错误（退出码 2），**不得回落代码里的默认值**。

### D14 · 退出码三语义锁进测试

`0` = 达标 / `1` = 未达标或检出不符合 / `2` = 输入、坐标或用例名错误。`--only` 传未知名必须走 exit 2。

### D15 · 字段映射歧义绝不猜

同一列名可能指多个参数时 → `not_provided(mapping_uncertain)` 显式第三态；**未登记列名同样 `not_provided`**（不抛错不臆测）。**映射与单位换算共用同一张别名表**。

### D16 · 解析不到 = 显式降级，绝不臆测

无法解析的字段落 `未提供` + **原因码**（`not_found` / `mapping_uncertain` / `structure_broken`），**绝不把"解析不到"当成"合规"或"违规"**。

### D17 · 批量通路：失败件 ≠ 违规

① 坏文件/不可解析是**未判定**（记 `scan_error`），**不改变退出码**（退出码仍由"是否检出 fail"决定）；② **失败隔离**——单件异常不中断整批（`kind="failed"` 继续跑）；③ 超大输入有安全阀。**单件与批量必须共用同一分派点**（`engine.check_card`），两条通路各写一套分派 = 最隐蔽的口径漂移。

### D18 · 两轮对账的配对主键 = 稳定身份键

`scan --baseline` 四类集（新增违规 / 已修复 / 持续违规 / 稳定）。配对主键用 `card:<card_id>` / `file:<相对路径>`，**不用内容指纹**——用指纹时"已修复"必然内容变了 → 永远配不上 → "已修复"永远检不出。指纹变化另立 `content_changed` 标记。

## 四、LLM 使用决策

**决策：不使用 LLM。** 全链路零 LLM。

**理由**（对应 skill 阶段 4"完全不用 LLM 是合法形态"）：
- 领域是**纯确定性规则 + 结构化输入**（法规条款 + 国标阈值 + 贴文本标签），没有"非结构化解析兜底"需求；
- 标签文本解析用规则优先（正则 + 槽位 + 合法性校验）足够，OCR 留扩展；
- 收益：结论 100% 可复现、零 API 依赖、基准可离线跑、脱敏面无外部调用、无幻觉风险。

**此形态下阶段 4 整体跳过**，省下的精力全投数据核对（M1）与基准（M4）。

## 六、架构风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| GB/T 31216/31217 全文机器直连拿不到 | 营养限值规则包无数据源 | **M1 数据先行**：浏览器会话录入数值表，逐条挂条款核对后转 `verified`；未录入前规则包条目全部 `pending`，门控拦下，报告显式呈现"未启用" |
| 标签规定全文需从公告附件提取 | 标示项规则无条款锚点 | 官方/权威原文快照入仓 `data/knowledge/raw/`，逐条核对后转 `verified` |
| 老解释器 + 重 GUI 依赖硬上限 | 3.8 装不了 PySide6 6.7+ | 已实测锁定 6.6.3.1；发布构建固定用 `py -3.12` 通道（PyInstaller ≥6） |
| 冻结产物跨平台字节漂移 | CI ubuntu 首跑红 | 生成器确定性 RNG + 固定时间戳 + 无平台元数据；`--check` 位级一致守门 |
| 编码差异（windows 红 / ubuntu 绿） | CI 首跑失败 | 三层加固：CI `env PYTHONUTF8=1` + 入口 `reconfigure` + 子进程显式 `encoding=` |
