**渠道坑实录（M0）**：
- Git Bash 的 `/tmp` 与 Windows Python 路径不通 → 临时文件一律用**工作区相对路径** `.tmp/`；
- 大文件同步 `curl` 超时 → `-C -` 断点续传 + 后台任务；
- `pdfimages -list` 在字形转曲线 PDF 上返回 0 行——**"PDF 有 95 页"不等于"能提取文字"**，入库前必须实测汉字数。

## 四、合成数据纪律

- 演示与基准一律使用**合成标签**，程序化生成、带植入真值，可一条命令复现评测；
- **假品牌名白名单**：合成品牌统一使用虚构名称（`测试粮A`–`测试粮F`，登记于 `src/pflc/benchmark/cases.py` 的 `BRAND_WHITELIST`）；**生成器硬断言**品牌名必须命中白名单，否则 exit 1；禁止真实品牌标签入库为基准样例；
- **真值样例参照**：规则包录入核对时，可引用 Royal Canin US / Orijen US 产品页公开 Guaranteed Analysis 实测值作参照，**必须记抓取日期与来源 URL**；该类真实数据仅用于录入核对参照，与合成基准**严格隔离**，不入基准真值库；
- 全本地零上传：标签文本、判定结果、基准样例均不出机；规则包未挂原文核对（`status=pending`）不得进入核查路径。

## 五、规则包形态与门控（M0 定稿）

### 5.1 目录与文件

```
data/rules/
├── ruleset-label.json      # 强制标示项规则（依据：宠物饲料标签规定）
├── ruleset-nutrition.json  # 营养限值规则（依据：GB/T 31216 / 31217）
├── ruleset-claim.json      # 宣称用语规则
└── manifest.json           # 版本锚点 + 验收门槛下发 + 覆盖登记 + 来源块

data/knowledge/
├── clauses/sources.json    # 参数来源登记（发布机关/文号/URL/抓取日期/sha256）
├── clauses/{label,nutrition,claim}.json   # 条文块（人工/脚本录入）
└── raw/                    # 官方/权威原文快照（.gitattributes 标 -text 防 EOL 改写）
```

### 5.2 双重门控（每条规则两个独立状态）

| 字段 | 语义 | 作用 |
|---|---|---|
| `status` | **数值**核对状态（`verified`/`pending`） | **唯一门控判定路径**的开关 |
| `clause_status` | **条款号**核对状态（`verified`/`pending`） | 只管可证性展示，**不阻断判定** |

门控还**按计算路径分作用域**（`label`/`nutrition`/`claim`），各只校验自己引用的条目——不用"整包全 verified"当唯一门，否则与某路径无关的 pending 会阻断整条路径。

### 5.3 冻结与守门

- 规则包是**冻结产物，禁手改**：改需求走 `tools/gen_rulesets.py --force` 整目录重生成；
- **位级一致守门**：`tools/gen_rulesets.py --check` 输出 `FROZEN_RULESET_OK`（并有 pytest 守门测试随全量测试运行）；
- **零政策字面量门禁**：禁用 token 从规则包**运行时实算**（源码与留档零词面），扫描引擎/基准/CLI/GUI 源码含 docstring 与注释。

### 5.4 覆盖登记（防"假覆盖"）

`manifest.json` 的 `coverage` 逐维度登记 **"规则包总数 / 已核对数 / 真值库采样数 / 采样清单"**，并显式声明"**抽样覆盖、非逐因素穷举**"——只写分子不写分母就是假覆盖。

### 5.5 验收门槛（数据非代码）

`manifest.json` 的 `thresholds`（`min_accuracy` / `max_false_positive` / `max_runtime_sec`）**随规则包下发**，基准层**只读**；缺失即报配置错误（exit 2），**不得回落代码里的默认值**。
